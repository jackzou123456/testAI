# 用报名数据做一次自己的尝试
使用者：由你选择，可以是课程组织者，也可以是希望了解学习情况的人。
输入：本工程 data/registrations.csv，180 条虚构报名记录。
目标：选一个有价值的问题，做出可以运行和检查的小成果。

## 自选方向，不必全部完成
先跑通当前版本，再选择一个小目标，也可以提出自己的问题：
- 查找：按城市、部门、课程或状态筛选、搜索。
- 比较：按一个维度汇总人数和实际时长，做表格或图表。
- 趋势：按 registered_on 报名日期观察月度变化。
- 进度：比较状态、计划与实际时长；先说明是否排除取消报名。
- 成绩与反馈：只用有效成绩计算，或整理反馈主题并保留原文依据。
- 外观与输出：让页面更清楚，或把现有结果导出成便于阅读的文件。

先做一个能运行、能检查的改动，有余力再组合功能。HTML 和 Python 不必互相依赖。

## 边界
原始 CSV 保持不变，输出写入新文件。先不增加账号、数据库或付费 API。
基于当前已能运行的版本开始，不要求换语言或同时完成两版。

## 怎样算完成
说明你的目标、统计范围和检查方法，再运行验证。
筛选可检查命中、无结果和恢复；图表核对明细与汇总；导出重开核对；界面检查窄屏和点击。
180 人、398 小时是全部报名（含取消）的数据参考，不是每项功能都必须显示的指标。
成绩空白不等于零分；完成率必须先确定分母。详见 数据说明.md 与 检查清单.md。
说明实际验证和未验证部分。reference 只是部门分析方向的参考，不是唯一答案。

## 可选：不指定图表库 vs 指定 ECharts
用 HTML 网页版的同一初版复制 A、B 两份，同一个模型和配置，各开一段新对话。可两人分工。
两组共同任务：
> 用 data/registrations.csv 做一个各部门报名人数的柱状图网页，同时显示明细和总人数。按全部报名记录统计，包含已取消的报名。希望能查看每根柱的准确人数，在手机上也能看清。保留原始数据，不增加后端；请实际检查结果，并说明用了什么绘图方式或库。

A 组不添加库要求；B 组只补一句“请明确使用 ECharts 绘制图表。”
B 可使用工程已有 vendor/echarts.min.js 离线运行。两组都有相同项目文件，现有库和说明也可能影响选择。
先看代码确认实际用了什么，再比较数据准确性、标签与读数、交互和手机布局；再给两版同样的横向柱状图修改任务。
全部 180，研发 49、销售 41，其余部门对照原始数据；不能把答案写死。
不指定库不等于禁用 ECharts，A 也可能选它。记录真实结果，不强行制造差异，也不凭一次生成断言哪种方式总是更好。
Python 学员可继续自己的分析，有兴趣再用 HTML 起点参与，不必连接两版。
